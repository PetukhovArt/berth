# Gotchas

The traps that outlive the task that found them — a platform or tool quirk, a required ordering, a
signal that lies, a settled decision. One line each, grouped by area, each opening with the thing it
is about. Read the sections your task touches before you start: a line here is a mine somebody
already stepped on.

Every line ends with `⟵ <slug>` — the task write-up it was distilled from. Those write-ups are
not in the tree; they went with the old project-memory system in `0415b71` and live in git history:

```
git show 0415b71^:.claude/memory/entries/<slug>.md
```

Two things to know before trusting a line. **It describes what was true when it was written** — if
one names a file, flag or symbol, grep for it before relying on it. **All of it predates two renames**,
nebula to pacer before the first release and pacer to berth after 0.20: env vars are `BERTH_*`, the
data dir is berth's (see DATA DIR), the database is `berth.db` and the hook tag is `_berthManaged`. Lines below have been respelled; the `⟵` slugs have not, because they are
filenames in git history and only resolve spelled the way they were written.

The ALL-CAPS lead-in is the old memory log's index key, not the project vocabulary; `GLOSSARY.md`
holds the terms. Nothing enforces this file any more — the caps and the `make memory-check` that
kept them are gone. A line whose trap a test or a type now catches should be deleted, not kept for
history.

## The tree
- **EXTERNAL SESSION** — An archive mark is a watermark, not a flag: the desktop app hides the row only while the transcript's mtime (`updated_at`) is at or before the daemon's `archived_at`, so new activity brings it back without anyone deleting the mark, and a test that archives then appends to the transcript sees it return. Never let archive or restore touch the transcript file or the process running it.
- **EXTERNAL SESSION** — Claude Code's `/clear` keeps the process but starts a new session id (SessionStart `source: clear`): the agent row adopts the new id and the old transcript turns into an external session, so the daemon archives it right there.
- **ROOT WORKTREE** — `git rev-parse --show-toplevel` inside a linked worktree returns the worktree, not the repo; `git worktree list --porcelain` always lists the main checkout first and is the reliable root oracle. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **ROOT WORKTREE** — git will swap a root's and a worktree's branches (`git switch --ignore-other-worktrees <wt-branch>` succeeds in the root), so a "wrong" ROOT BADGE can be reality — check `git worktree list` first. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **TERMINAL SESSION** — The Aug 9 removal of terminals reads like a settled decision in the history and is not one (they came back) — don't cite it as precedent. ⟵ 2026-08-09-terminals-removed-then-brought-back
- **WORKSPACE** — `workspace = None` must survive for connections that never `Subscribe` — the one-shot `berth add`, whose workspace genuinely is the current default; don't default it at connect time. ⟵ 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **WORKSPACE** — A WORKSPACE is just a grouping of PROJECTS and the same PROJECT may belong to several — refusing to add a project already in another workspace was rejected by the user. ⟵ 2026-08-21-workspaces-and-the-o-t-e-hotkey-remap

## Processes and plumbing
- **DAEMON LOG** — DAEMON LOG records no hook traffic at `info` (`hook received` is `debug`; `hookEvent=` never appears), so the SQLITE STORE row (`claude_session_id` on `agents`) is the only cheap live oracle for status timing. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **DAEMON SETSID** — Garbage tokens on the terminal that started the daemon were a shell job-control fight over the controlling terminal, not vt100: a new process group is not enough — a new session makes zsh's `/dev/tty` open fail so it skips job-control init. ⟵ 2026-08-20-the-daemon-needs-its-own-session-not-just-a-process-group
- **DATA DIR** — The real DATA DIR is `~/Library/Application Support/dev.berth/` on macOS (`ProjectDirs::from("dev","","berth")`), `$XDG_DATA_HOME/berth` (else `~/.local/share/berth`) on Linux, `%APPDATA%\berth\data` on Windows; nothing prints it. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **DATA DIR** — The pacer → berth rename is a one-shot COPY in `pacer_migration::run`, called first thing in `main` for every subcommand: berth's DATA DIR existing at all is the "already migrated" flag, so anything that creates it before `main` runs (log init, a config write) silently skips the copy forever, and any `berth` run without `BERTH_DATA_DIR` (a test spawning `CARGO_BIN_EXE_berth`, a smoke check) snapshots the real pacer data into the real berth dir — give every such spawn its own `BERTH_DATA_DIR`. Old names live only in `berth-core/src/legacy.rs`.
- **DATA DIR** — Opening a WAL database read-only still creates its `-wal`/`-shm` when they are missing, so the migration file-copies `pacer.db` when no `pacer.db-wal` exists and only uses `VACUUM INTO` over a read-only connection when one does (a live or crashed pacer daemon); that is what leaves pacer's directory byte-identical. On Windows `directories` asks the shell for `FOLDERID_RoamingAppData`, so a temp `APPDATA` does not redirect the default path — test the copy with `PACER_DATA_DIR` plus `BERTH_DATA_DIR`.
- **LOGIN SHELL PATH** — `platform::login_shell_path()` costs one `$SHELL -l -i -c` start (capped at 3 s) and its result goes into the process env with `set_var`, so the desktop calls it, through `platform::adopt_login_shell_path`, as the first line of `desktop::run`, before tauri or tokio start a thread: a `getenv` on another thread (WebKit, any C library) races `setenv`. Moving it later or onto a thread needs every spawn site to take the PATH explicitly instead.
- **MIGRATION** — Migrations 2, 3, 7 and the migration-14 rebuild still spell out the divider columns and must — they already ran on every DB; only migration 18 drops them, so don't "tidy" old SQL. ⟵ 2026-08-25-project-dividers-removed-from-the-projects-column
- **PTY SESSION** — Agent PTYs get `TERM=xterm-256color` (`pty/mod.rs`) but inherit the daemon's `TERM_PROGRAM`, so `/terminal-setup` inside berth detects the terminal the daemon was first spawned from, not the one attached. ⟵ 2026-08-18-cmd-p-never-reaches-the-agent-in-terminal-app
- **RUNTIME DIR** — SUN_LEN is 104 bytes on macOS, so a RUNTIME DIR holding the DAEMON SOCKET must stay short: the default is `/tmp/berth-{uid}` or `$XDG_RUNTIME_DIR/berth`, `make dev` uses an 8-hex path hash (`/tmp/berth-dev-<8hex>`), never the worktree name; for a hand-set `BERTH_RUNTIME_DIR` use short dirs like `/tmp/nbws`. ⟵ 2026-08-26-one-nebula-per-checkout-auto-port-for-browser-per-path-dev-s; 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **SQLITE STORE** — A `COALESCE(workspace_id, ?1)` inside a shared `*_COLUMNS` const makes every query using it bind a hidden first parameter; rusqlite only checks bind counts, so a `WHERE workspace_id = ?1` would silently COALESCE NULL rows — select the bare column and apply `DEFAULT_WORKSPACE_ID` in `row_to_project`. ⟵ 2026-08-27-workspace-wide-dedup-pass-named-literals-shared-helpers-nebu
- **SQLITE STORE** — `sqlite3 ".backup"` reads the WAL, so the snapshot is consistent with the daemon still running; a plain `cp berth.db` misses everything in `berth.db-wal`. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **VENDORED VT100** — Codex is a ratatui inline-viewport app scrolling inside a top-anchored DECSTBM region (`ESC[1;{viewport_top}r`); stock vt100 0.15.2 `grid.rs` `scroll_up` discards lines scrolled out of a region, so codex scrollback stayed empty. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — `vendor/vt100` is a patched fork — do not upgrade or re-vendor it without re-applying the scroll-region patch. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — Full-screen (alternate screen) apps are unaffected: that grid is created with zero scrollback capacity. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VERSION SKEW** — A PROTOCOL VERSION bump means the daemon still running from before the build refuses the new client until BERTH KILL (or MAKE CYCLE) restarts it — expected; the client offers the kill-and-restart. But `berth kill` is wrong advice when the *client* is the older side: the `berth` command respawns an identical daemon from `current_exe()` (`spawn_daemon` in `crates/berth/src/client.rs`). `buildstamp_path()` (`<runtime dir>/daemon.build`) holds only a content fingerprint of the daemon's exe, not where it lives — pidfile + `ps` names the binary. ⟵ 2026-08-28-r-renames-a-project-row-without-touching-its-folder; 2026-08-28-released-v0-15-0-by-cherry-picking-only-the-post-v0-14-0-del; 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis · re-hit ×2 2026-08-28 · retire: `pacer rename` over the HOOK RECEIVER instead of the versioned socket
- **VERSION SKEW** — The desktop app starts `berth daemon` from the `berth.exe` beside it (Windows searches the caller's directory before `PATH`), so after an app update the daemon is newer than `~\.cargo\bin\berth.exe`. Every PTY therefore gets the daemon's own directory first in `PATH` (`pty/own_dir.rs`), with the app's `current` link resolved to the build it points at. A unix agent launch goes through the login shell, whose profile can still put another `berth` in front. ⟵ 2026-11-11-berth-rename-v40-against-a-v41-daemon
- **VERSION SKEW** — A new `ClientRequest` variant needs the PROTOCOL VERSION bump too: the daemon's `read_frame` fails on an unknown variant and drops the whole connection, so an older daemon would kill the client instead of answering. The running `tauri dev` desktop rebuilds itself on the bump and turns Incompatible at once. To rebuild the dev daemon, close the dev app first: while it runs it respawns `target\debug\berth.exe daemon` about 0.1 s after `berth kill`, so `cargo build -p berth` fails with `Access is denied (os error 5)` on Windows. Then build and start the dev app again; it brings up the new daemon itself. ⟵ 2026-11-06-list-branches; 2026-11-18 dev daemon restart check
- **VERSION SKEW** — Do not add a field to `ServerEvent::Incompatible`: a newer daemon sends it to an older client and rmp is positional, so those clients fail to decode it ("unexpected handshake reply"). ⟵ 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis

## Status and badges
- **ATTENTION** — "Does this session need me, and how urgently" is answered once, by `entities/session/lib/attention.ts` over the Session state from `useSessionStates` (`model/sessionState.ts`): needs feedback, then crashed (Terminated; a restored CLI that dies while Disconnected becomes Terminated in the daemon), then limit, then finished and Unseen, then running. The Inbox, toasts, `Alt+J`, Hot sessions, the Rollup and the tray read it; a new place that asks re-derives nothing from `SessionNode.status`, which carries neither the linked conversation nor the limit.
- **EXTERNAL SESSION STATUS** — `agent_sessions.rs` `status_of` reads an External Session's status from the transcript tail and reports Agent Status words (`running`, `finished`, `closed`), which the web shows as they are. An ended turn is Finished, never Needs Feedback: an External Session has no Unseen to stand in for, and the transcript cannot tell a permission prompt from a tool call in flight (both end on an assistant `tool_use`, read as running). Report `needs_feedback` from there only once it is reliably detectable.
- **DONE BADGE** — The counter is daemon-side: `set_agent_status` applies `berth_core::attention` (`AttentionState::change`) to the row it reads under the store lock, not `AgentStatusMachine` (which dedups unchanged statuses); NEEDS FEEDBACK → FINISHED counts, FRESH → FINISHED does not. ⟵ 2026-08-26-unwatched-finishes-count-on-the-project-and-worktree-rows
- **PROGRESS SCANNER** — Esc-cancelling a Claude turn fires no hook at all: `Stop` skips user interrupts and `idle_prompt` needs 60s quiet AND no keyboard touch (Claude Code 2.1.241: only `UserPromptSubmit` then `SessionEnd` fired). ⟵ 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — Claude Code 2.1.270, Codex and cursor-agent emit **no OSC 9;4 at all** — not at startup, not on submit, not on a cancel — so `progress_busy` reads `None` forever and every Claude row wedged on yellow after `Esc`; the title is Claude's fallback (see TITLE SCANNER). Re-check a new release with `cargo test -p berth-daemon --test conpty_progress_probe -- --ignored`. ⟵ 2026-09-15 escape-did-not-cancel-the-animation; 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — `ProgressScanner::feed` reports *edges*, so an end-of-turn that lands before the status moves (the cancel, then the permission hook) is spent and nothing is left to un-wedge the row; `AgentStatusMachine::tick` reads the *level* (`PtySession::progress_busy`) as the backstop, and needs two sightings so a `UserPromptSubmit` that beat the CLI's own busy byte can't read as finished.
- **STOP GATE** — `TaskStop`-killing a BACKGROUND SUBAGENT delivers no `SubagentStop` (a normal completion does), and `Esc` mid-turn kills the turn's background workers the same silent way — the orphan then gates every later turn of that session. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no; 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — A killed subagent is only distinguishable from a live silent one on disk: `"stoppedByUser": true` in `<transcript>/subagents/agent-<id>.meta.json`, read by `subagents.rs` on tick, where `<transcript>` is the payload's `transcript_path` minus `.jsonl`. Claude-only — codex and cursor still wait out the 30 min QUIET GRACE. ⟵ 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — `UserPromptSubmit` opens the Stop Gate (`StopGate::Open`) and resets the quiet clock but does *not* clear the tracked set (deliberately: background workers outlive a prompt), so an orphan survives every later prompt and the quiet clock restarts from each turn's hold, not from the kill. ⟵ 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — Subagent tool traffic reaches the STATUS MACHINE only for hooked tools (`PostToolUse` `Bash|EnterWorktree|ExitWorktree`, `AskUserQuestion`): a Read/Grep-only worker shows life only at start and stop, so the quiet clock must stay generous. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **STOP GATE** — The quiet clock counts from the last sign of life, not from the held Stop — a test written "from the hold" is off by the SubagentStart→Stop gap. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **TITLE SCANNER** — The OSC 0 title glyph (`✳` idle, `◐`/`◑` working) is the end-of-turn signal left once OSC 9;4 went away, but it reads idle while a permission prompt waits too — so `TitleIdle` may only close out a turn already on RUNNING, never one on NEEDS FEEDBACK, and may never start one. Relaxing that gate greens out every agent waiting on the user. ⟵ 2026-09-15 escape-did-not-cancel-the-animation
- **TITLE SCANNER** — The glyph is only there because `showStatusInTerminalTab` is off by default; turning it on strips the prefix and the fallback goes quiet (not wrong — cancels just wedge again). Codex and cursor title themselves without it, so the path is inert for them either way. ⟵ 2026-09-15 escape-did-not-cancel-the-animation

## Desktop web UI
- **PHONE LAYOUT** — In a scoped style, write a phone rule as `:root[data-vr-viewport='phone'] .x`, never `:global(:root[data-vr-viewport='phone']) .x`: Vue compiles the `:global()` form to the bare `:root[...]` and drops ` .x`, so the rule lands on `<html>` itself and a `display: none` blanks the whole app on a phone. ⟵ 2026-11-16 design conformance check
- **PHONE LAYOUT** — The desktop web UI goes phone-shaped on `<html data-vr-viewport="phone">`, which `installViewport` (`packages/ui-kit/src/viewport.ts`) sets from `PHONE_QUERY` in `@ui/tokens`; a component never writes a width media query, it uses the `vr-*` primitives in `packages/ui-kit/src/responsive.css`. Growing a touch target with a `::after` past the button's box steals taps from the next row of a dense list (later siblings paint on top), so the kit sizes rows (`--vr-size-row`) and icon buttons instead. ⟵ 2026-11-06-the-web-ui-fits-a-phone
- **PHONE EMULATION** — In WebView2, CDP `Emulation.setDeviceMetricsOverride` with `deviceScaleFactor: 3` changes `devicePixelRatio` but not `devicePixelContentBoxSize` (it stays at the monitor's scale), so the xterm WebGL canvas gets a 1.25x backing store and 3x glyphs: the terminal looks 2.4x too big and clipped on the right. That is the emulator, not the app; judge the terminal at `deviceScaleFactor: 0`.
- **HOST TEXT** — Text the desktop's Rust hands the UI (an `Err`, a health detail, a plan label) is never a literal in one language: it is `crate::host_text!("code", name = value)`, a `\u{1e}{"code","params"}\u{1f}` segment inside a plain `String`, translated from `host.<code>` in `apps/web/src/shared/lib/i18n/{en,ru}/host.ts`. The web decodes it in `bridge.ts` for `invoke` results and rejections, `listen` payloads and `createHostChannel` messages; a plain `createChannel` (the `berth_watch` stream) is not decoded, so its texts go through `hostText` where they render (`NavNotices.vue`). Code that branches on an error matches the code or `ApiError::has_status`, never the wording. Daemon errors (`ServerEvent::Error`) are still English text: coding them needs a protocol change.
- **TYPE SCALE** — The `ui.font_size` setting sets one variable, `--vr-font-scale` on `<html>` (`apps/web/src/shared/ui/appearance.ts`); every `--vr-font-size-*` and `--vr-font-leading-*` token is generated as `calc(Npx * var(--vr-font-scale))` (`packages/ui-tokens/scripts/build.ts`) and the root `font-size` follows it, so PrimeVue's `rem` scales too. A raw `px`/`rem`/`pt` `font-size` or `line-height` never scales: use a token, `em`/`%` of a token, or a unitless line height; a box that must fit its text (badge, counter) is sized in `em`. A new size step goes into `packages/ui-tokens/tokens/primitive.json`, then `pnpm build:tokens` (`generated/` is gitignored, a stale copy keeps old values). Reading a font token from JS gets the `calc(…)` string, not pixels.
- **STATUS DOT** — `ui.statusAnimation` (`apps/web/src/shared/ui/motion/statusAnimation.css`) animates only a `.status-dot` carrying `data-status`/`data-unseen`, inside a `.status-host` for the `row` style; render a session's status through `StatusDot` (`entities/session`), never a bare `StatusIcon`, or that place stops animating. The dot is a `<span>` around the icon because Chromium/WebView2 draws no `::before`/`::after` on an inline `<svg>`, which is where the ripple rings live.
- **TERMINAL THEME** — Any xterm `ITheme` key `SessionPanel.vue` leaves unset falls back to xterm's dark-tuned default, so on the light theme white and bright yellow text vanish; every ANSI color, selection and scrollbar key comes from a `--vr-term-*` token in both `semantic.*.json`, each of the 16 foregrounds at WCAG ≥ 4.5 against `surface-sunken` (≥ 3 for black on dark and white on light). `xterm.css` hardcodes the IME `.composition-view` colors, which `SessionPanel.vue` overrides.
- **MOTION SWITCH** — `ui.animations` off and the OS reduced-motion query only shrink `var(--vr-motion-*)` (`packages/ui-tokens/generated/motion.css`) and gate JS through `isMotionEnabled()`; a literal duration in our code, or one inside a library's CSS, keeps moving. Library motion is pinned where the library is themed: PrimeVue in `packages/ui-kit/src/overlays.css` and the preset in `packages/ui-kit/src/index.ts`, dockview in `DockArea.vue` (its own `--dv-transition-duration`, the rest cut off under `.vr-reduce-motion`).
- **DAEMON DEFAULTS** — The defaults of every setting the desktop mirrors into the daemon's CONFIG.JSON live once, in `crates/berth-core/daemon-defaults.json`: `schema.ts` imports it, `Config::default()` and the desktop's `berth_*_read` fallbacks read it through `berth_core::daemon_defaults()`. A key added there needs its `DaemonDefaults` field (`deny_unknown_fields` fails the core test otherwise), and the Docker image's web stage copies only `apps/web` and `packages`, so the file has its own `COPY` line in `docker/Dockerfile`.
- **DAEMON DEFAULTS** — `berthIdle.ts` lets the daemon's value win on every pull, so a setting that existed in the UI before it was mirrored would be reset to the default by the first pull; such a key's `_read` returns `null` while CONFIG.JSON lacks it (`berth_worktree_base_read`), and the pull then writes the UI's value to the daemon instead.
- **LIVE LANGUAGE** — `ui.language` switches without a reload, so a `t()` result computed once (a module-scope options array, a dockview panel `title`) stays in the old language: build option lists in `computed`, open a dock panel with `params: titleKey(…)` and render it through `panelTitle` (`shared/model/dock.ts`). PrimeVue's own strings (empty filter, dialog close, selection) come from `app/kitLocale.ts`; dates and sorting go through `formatDate`/`formatTime`/`compareText` in `shared/lib/i18n`, never the OS locale.
- **SPLASH THEME** — The splash in `apps/web/index.html` paints before any app code or bundled CSS, so it picks `vr-dark` itself from the cached settings text (`berth.settings.cache` in the desktop app, `berth.settings.json` in a browser, see `shared/lib/config-file/backend.ts`) and `prefers-color-scheme` for `system`, and its colors are `var(--vr-…)` tokens that the `berth-splash-tokens` plugin in `apps/web/vite.config.ts` inlines into `<head>`; a hex there drifts from the tokens.
- **PHONE TERMINAL** — A Session has one PTY, so a terminal that attaches or fits resizes it for every client: the daemon answers `Attach` with `resize_with_jiggle` and `Resize` with `resize` (`crates/berth-daemon/src/server.rs`), and a phone's xterm at about 40 columns squeezed the same Session's terminal on the desktop. On a phone `sessionView.ts` makes the Terminal view unavailable for a berth Session, so `SessionPanel` never mounts there; a new phone path that attaches a terminal must not send its size.
- **BACKGROUND WORK** — Behavior that must happen with no window open, from a phone, or under `berth-server` (archive on merge, tracker write-back, watching a merge request) lives in `berth-desktop` Rust, not in the web UI: a web feature runs only while a webview is open and visible, and once per open client. `merge_watch::run` holds `merge-watch.lock` in the daemon's runtime dir so the desktop app and `berth-server` on one machine never both act, keeps its own state (archived list, what each watched merge request last showed, prompts held for a busy Agent) in `merge-watch.json` in the daemon's data dir and only reads `merge-watch-list.json`, the watched merge requests that the `merge_watch_set` command alone writes, and does not run when the desktop app is attached over ssh (`BERTH_REMOTE`), because the worktree paths live on the other machine; run `berth-server` there instead.
- **DOCKVIEW HMR** — A dock panel with `renderer: 'always'` keeps the component instance it was created with across Vite HMR, so a template change inside one looks unapplied; press F5 before judging it. ⟵ 2026-11-06-the-web-ui-fits-a-phone
- **KIT CSS AFTER MERGE** — A running `tauri dev` can keep serving the old scoped CSS of a `packages/ui-kit` component after a `git merge` brings in a new version of it, F5 included (seen with `ChipGroup.vue`: the page still had `flex-wrap: wrap`); restart the dev app before judging a kit change, and read the computed style, not the source. ⟵ 2026-11-22 global search

## Agents and hooks
- **CLAUDE MOD** — Claude 2.1.287+ reports through berth's mod (`hooks/claude_mod.rs`, laid out in `<data dir>/claude-mod`, passed as `--plugin-dir`), not through shell hooks: its `classic.<Event>` handlers get the same stdin JSON and run in-process, so a tool call costs no bash+curl. An older Claude, or a machine whose managed settings set `allowManagedModsOnly`, falls back to the `settings.local.json` shell hooks; never install both, or every event reaches the daemon twice. The mod's `UserPromptSubmit`/`SessionStart` wait for the daemon (their reply is context); every other event is posted without waiting.
- **HOOK TAG** — berth treats pacer's hook groups (`_pacerManaged`, or a command naming `PACER_AGENT_ID`) as its own, so a berth spawn replaces them; pacer 0.20 does not know `_berthManaged`, so a pacer spawn in the same checkout or `~/.codex` adds its groups back beside berth's. Both sets stay inert outside their own sessions only because the daemon scrubs the other product's `*_AGENT_ID`/`*_API_*` from every PTY (`env::AGENT_SESSION_VARS`): drop the `PACER_*` names from that list and a berth started inside a pacer pane posts its sessions' hooks to pacer's daemon. The `Bash(pacer …)` permission rules are left in `settings.local.json` on purpose.
- **AGENT KIND** — Every CLI takes a trailing positional prompt (`claude [prompt]`, `codex [PROMPT]` / `codex resume [SESSION_ID] [PROMPT]`, `cursor-agent [prompt...]`), but only Claude's `--resume <sid> "<prompt>"` is verified live — the RELOCATION PROMPT is Claude-only for that reason. ⟵ 2026-08-28-agent-presets-launch-a-session-with-a-composed-first-prompt · retire: a live codex/cursor resume-with-prompt check
- **AUTO-TITLE** — The `berth rename` every session issues before anything else is injected context from the AUTO-TITLE INSTRUCTION, not something the user typed — don't mistake it for part of the request. ⟵ 2026-08-20-sessions-auto-rename-themselves
- **CLI RENAME** — No hook fires on Claude's or Codex's `/rename`. Claude rewrites `<transcript stem>/custom-title.json` (and `~/.claude/sessions/<pid>.json` `name` with `nameSource: "user"`) and re-appends the same `custom-title` line to the transcript all the time, so a line is not news; Codex appends `{id, thread_name, updated_at}` to `$CODEX_HOME/session_index.jsonl`. A rename is a change of `agents.cli_title`, never a difference from `name`, or a berth rename is undone on the next sampler tick (`crate::cli_title`).
- **CLI RENAME** — A `claude` the user starts by hand in a terminal is found by pid: Claude keeps `<CLAUDE_CONFIG_DIR or ~/.claude>/sessions/<pid>.json` while it runs, and only `nameSource: "user"` is a `/rename` (`"derived"` is Claude's own name; `formerNames` lists the old ones). The sampler walks the terminal's process subtree for it and stores `terminals.cli_title` the same way as agents. Codex keeps no record by pid, so a hand-started Codex in a terminal is not followed. A process that names its conversation (that `sessionId`, or `--resume`) is matched to it only by id in `agent_sessions::claim`: a fresh Claude has an id whose transcript does not exist yet, and the start-time guess handed it the newest closed conversation in its folder, hiding that row. No supported way exists to push a berth name into Claude's own title, so `/resume` keeps Claude's.
- **CLI RENAME** — The same `<pid>.json` carries `sessionId`, so the sampler also stores `terminals.session_id`, the conversation a terminal last ran; the desktop app ties a closed conversation to its terminal by that id, never by the terminal's name, whether the terminal is dead or alive: a daemon restart or a crash can restore a terminal as a bare shell, so requiring a dead one made Continue open a second terminal of the same name. A clean shutdown records which terminals ran Claude in the live-sessions list, and their first spawn after the restart types `claude --resume <id>` (`crate::terminal_resume`). A Claude that exits before a sampler tick, or ran before the daemon recorded it, leaves no id, and its conversation lists on its own.
- **EXTERNAL SESSION** — Continue never types `claude --resume` into a terminal any more: a CLI in a terminal has no `BERTH_AGENT_ID`, so it sends no hooks (no Allow/Deny, no attention, no resume). `ResumeConversation` (`crate::resume_conversation`) makes it an agent: it reuses an agent row that already carries the id (moved to the target worktree, unarchived), refuses while an agent or a terminal runs it, and then closes every terminal holding that `session_id` whose shell has no child process. The tree also hides a dead terminal whose `session_id` an agent owns, so a stale id never shows a second row of the same name.

## Daemon mechanisms
- **PTY ATTACH** — An attached client follows the SessionRef, not the process: `forward_pty` rebinds to whatever PTY `install_session` publishes on `installed_sessions` for its ref (restart, model switch, move, `berth worktree` relocation). A respawn path that puts a PTY in the map without `install_session` leaves every open terminal showing `[session ended]` over a session that is running.
- **IDLE REAPER** — Reaping is switchable off entirely (`session_idle_timeout = off`) because agents may be running long jobs the status machine cannot see; the PIN exemption that used to protect them was removed with PIN on 2026-08-28 — do not reintroduce a per-session spare without the user. ⟵ 2026-08-20-idle-session-reaping-and-metrics; 2026-08-28-pin-and-the-recent-group-are-gone-one-flat-list-in-recency
- **METRICS** — `GetMetrics` no longer sweeps: `crate::sampler` is the single owner of the CPU delta and the transcript offsets, and the request reads its last sample. Measuring per request dates every delta from whichever client asked last. Before the sampler's first tick the daemon still replies, with `MetricsSnapshot::unsampled()`: the client frees its pending slot on the reply, so silence leaked one slot per poll. ⟵ 2026-09-22-diagnostics-card
- **PREWARM POOL** — One WARM SPARE per daemon, not per project (`crate::prewarm`): one spare per (worktree, kind) once meant 7 projects ≈ 7 idle `claude`s ≈ 1.7 GB. A prewarm for another target kills the spare and boots the new one; it lives 15 min (`PREWARM_MAX_AGE`). The opt-out is `prewarm` in CONFIG.JSON (renamed from `prewarm_agents` by `config::adopt_renamed_keys` at daemon start, because a serde `alias` errors "duplicate field" when a file holds both names and the whole config falls back to defaults); turning it off kills the spare on the next 30 s tick. ⟵ 2026-08-27-the-memory-modal-s-unknown-agents-are-the-prewarm-pool
- **PREWARM POOL** — The pool is empty until a new-session form is open on an existing worktree (`warmTarget` in `NewSessionForm.vue` needs `plan.kind === 'use'`): a create that makes its worktree (New worktree, or an existing branch with no checkout) is always cold, and the spare booted for the form's default target is wasted until `PREWARM_MAX_AGE`. Measured on a real data dir over 6 days: of 60 spares 32 were never adopted (17 died at the 15 min expiry), and 10 of 25 user cold creates made a new worktree. `openInSession` (MR / Jira) and `berth spawn` never touch the pool either.
- **NEW WORKTREE BASE** — The fetch behind New worktree runs in the desktop host, not the daemon (`new_worktree_base::worktree_base_source`, called by `sessionTarget.ts` only when `plan.fetch`); the daemon's `CreateWorktree` never fetches (only `berth spawn --worktree` does, via `worktree_base::choose`). While the form is open `worktree_base_prefetch` runs the same fetch through `berth_core::fetch_gate::FetchGate`: fetches into one repo take turns, a ref fetched in the last 120 s is skipped, a failed one is not remembered. Measured on a 4000-file repo: the base fetch is 0.11-0.16 s against a local remote and 0.62-0.68 s against GitHub, `git worktree add` 0.9-1.5 s.
- **PREWARM POOL** — `ps -Eo command -p <pid>` shows a daemon child's `BERTH_AGENT_ID` / `BERTH_DATA_DIR` (macOS `ps -axo … -p` ignores `-p`, drop `-a`); `grep prewarm <data_dir>/state/daemon.log` maps the id to its spawn — branch only, so `main` repeats across projects. ⟵ 2026-08-27-the-memory-modal-s-unknown-agents-are-the-prewarm-pool
- **PREWARM POOL** — A starting prompt is typed into the WARM SPARE only after its `SessionStart` hook arrives, and only for Claude (`prewarm::signals_input_ready`): text typed into Claude at spawn is lost and the TUI stalls; bracketed paste (`?2004h`) comes on ~1 s before `SessionStart` and the paste lands, but it is on in front of the folder-trust dialog too, where the Enter would answer "trust"; project hooks, berth's included, never fire until that dialog is answered. A spare younger than `SPARE_BOOT_BOUND` (8 s) is waited for, an older silent one is left alone and the create goes cold with the prompt in argv. Codex, Cursor, OpenCode and Grok were not measured and stay cold. Measured on Windows, Claude Code 2.1.311 (`tests/prewarm_readiness_probe.rs`): spawn to `SessionStart` 2.3–3.4 s, cold argv prompt to `UserPromptSubmit` 3.0–3.7 s, typed into a booted spare 0.33–0.55 s.
- **AGENT MEMORY** — One `claude.exe` holds ~220 MB private working set idle and 300–400 MB after work (550–750 MB commit); its ~260 MB of code is image-mapped and shared between processes. Bun GC knobs in the spawn env do not move it: `BUN_OPTIONS=--smol` and `BUN_JSC_forceRAMSize` measured within noise, and a forced full GC frees ~30 MB. The lever is how many CLIs are alive (IDLE REAPER, PREWARM POOL), not tuning each one. Measured on Windows, Claude Code 2.1.292.
- **WORKTREE SEED** — `git ls-files --others --ignored --exclude-standard --directory` collapses a directory ignored *in full* into one `dir/` entry, so a symlink parked inside it (`.claude/skills/<skill>`) never appears; skipping every `dir/` entry therefore drops exactly the links `worktree_seed` exists to carry, which is why it also does a shallow pass inside them. A symlink to a directory is reported *without* a trailing slash, so the slash test never mistakes one for a directory.
- **WORKTREE SYNC** — Rebase state lives in the per-worktree git dir (`<repo>/.git/worktrees/<name>/rebase-merge/`), not the shared `.git` — `git_common_dir` in `lib.rs` deliberately hops to the shared one and is the wrong helper; use `rev-parse --absolute-git-dir` from the checkout. ⟵ 2026-08-27-a-paused-rebase-renamed-the-worktree-row-to-detached
- **WORKTREE SYNC** — `git worktree list` may print canonical paths while `add_worktree` returns the tempdir spelling (`/var/…` vs `/private/var/…` on macOS) — canonicalize both sides when a test needs to find the entry. ⟵ 2026-08-27-a-paused-rebase-renamed-the-worktree-row-to-detached
- **WORKTREE SYNC** — A probe that can't read anything is not a fingerprint: `.git` is a *file* in a linked worktree, so `.git/HEAD` stamps were `None == None` and the project never synced; never cache a `None` stamp. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **WORKTREE CLEANUP** — `rev-list base..HEAD` = 0 also holds for a branch created a minute ago with no commits, so reachability alone would offer a fresh worktree as merged; `apps/desktop/src-tauri/src/cleanup.rs` counts it merged only when the branch reflog moved past its creation entry. Squash merges never reach 0 at all, which is why the forge state is asked first. ⟵ 2026-11-06-worktree-cleanup
- **WORKTREE CLEANUP** — On Windows `git worktree remove --force` and recursive deletes descend into a `node_modules` junction and empty the main checkout's copy; unlink every reparse point with `lstat` (no follow) before the daemon's `DeleteWorktree`. ⟵ 2026-11-06-worktree-cleanup
- **SHARED SETUP** — In `create_worktree` the sync runs after `worktree_seed::seed`, never before: seed skips any path that already exists, so syncing first would create `.claude/settings.local.json` and keep the user's own copy from main out of the new Worktree. Seed instead carries main's installed files across, and a checkout with no manifest of its own starts from main's (`berth-setup.json` in the common git dir), which is how the sync recognises those copies as berth's and keeps updating them.
- **SHARED SETUP** — Cursor and Grok import hooks from `.claude/settings.local.json` (Cursor's "Third-Party Imports", on by default; Grok's Claude compat), and Grok also imports `.cursor/hooks.json`, so a shared hook written to every kind's own file runs twice there: `plan_hooks` writes Cursor's copy only when Claude does not get the hook, and Grok's only when neither Claude nor Cursor does. Sources: cursor.com/docs/reference/third-party-hooks, `crates/codegen/xai-grok-hooks/src/discovery.rs` in xai-org/grok-build.
- **SHARED SETUP** — Shared Codex hooks live in `$CODEX_HOME/hooks.json` for the same trust reason as berth's own (CODEX HOOK DIALECT), which makes them global: each command opens with a `grep` of `$(git rev-parse --git-common-dir)/berth-shared-hooks`, the per-repository list the sync writes, so a project-scoped hook stays inert elsewhere. The guard text names only the item, never a path, so the definition, and with it Codex's trust, is the same in every repository.
- **SETUP COMMAND** — A Project's setup command is the user's own text in the daemon database (`project_setup`, `worktree_setup.rs`), never read from the repo, so a checkout cannot make berth run anything; it is typed into a Terminal Session named `setup` of every Worktree `create_worktree` makes, which is how its output stays visible. `CreateWorktree` with a blank `branch` generates the name (`berth_core::branch_name`).
- **CHAT BRIDGE** — Telegram hands a bot's updates to one `getUpdates` reader at a time: a second daemon with the same `messenger_telegram_token` (a dev instance whose `config.json` was copied from the real one, or OpenClaw on the same bot) gets `409 Conflict` and the two split the owner's messages between them. A dev instance needs its own bot or no `messenger_telegram_owner`. Voice notes are transcribed by whichever desktop app connection sent `OfferTranscription` last (`messenger/transcribers.rs`, process-wide), so the daemon never links whisper.
- **HUB ROLES** — Every hub call a daemon makes for its Agents (`POST /agents`, any `as_agent` read or post, `/instruct/ceiling`) needs `agents.join`, which a Guest lacks, so a Guest's daemon is refused them on every round. The periodic loops (`run_channel_delivery`, `register_agents`, presence, overlaps, channel requests) log a hub refusal at debug and wait for their next tick; a new loop that warns or retries at once floods a Guest's log. Rights live only on the hub: the daemon caches none and refetches `/me` on each `GetHub`, and the app refetches on `HubChanged`, which the stream sends every time it goes live.

- **VOICE BUILD** — sherpa-onnx links as a DLL on Windows (`features = ["shared"]`), statically on macOS: its Windows static archives are `/MT` while `cmake-rs` builds whisper.cpp `/MD`, and two C++ runtimes in one link is LNK2038. `build.rs` delay-loads `sherpa-onnx-c-api.dll` so an app copied without the DLLs still starts, and `platform::speech_engine_loads` probes it with `LoadLibraryW` before the first call: a delay-load miss is an SEH crash, not an error. `scripts/install-app.ps1` copies `sherpa-onnx-c-api.dll` and the one DLL it imports, `onnxruntime.dll`, beside `berth-desktop.exe` (the build also drops `sherpa-onnx-cxx-api.dll` and `onnxruntime_providers_shared.dll`, which nothing loads on the CPU path); an update run by an older installed script leaves them out once. whisper.cpp adds an import of `MSVCP140.dll`, which a machine with the Build Tools has, and only such machines build the Windows app today. ⟵ 2026-11-16 local speech recognition
- **GIT BASH** — A Git Bash terminal's PTY child is the launcher `Git\bin\bash.exe`, which always runs `Git\usr\bin\bash.exe` under it, so `platform::has_child_processes(shell pid)` is never false there: "the shell is idle" cannot be read that way. Restoring a terminal's Claude therefore keys on the terminal's first spawn after the daemon starts (`crate::terminal_resume`), not on the shell having no child. Measured with the dev daemon's process tree, 2026-11-18.
- **E2E PTY** — `cmd.exe` given arguments it does not recognise opens an *interactive* shell, so it leaks one live child per test as a stub; `where.exe` takes the arguments, fails and exits. ## Other
- **RELEASE** — The `version` bump in the root `Cargo.toml` *is* the release: landing one on `main` builds the CLI for three targets (macOS arm64/x64, Windows x64) and the desktop app for four (plus Linux x64), tags the commit and publishes the GitHub release with the archives, the installers and `latest.json`. Never bump it as part of unrelated work.
- **RELEASE** — A tag or release created with `GITHUB_TOKEN` starts no workflow — GitHub's guard against a workflow triggering itself. So a release cannot hang off a tag CI pushed, and nothing can hang off `release: { types: [published] }`. `release.yml` does all of it in one run; the tag is the record of what shipped, not the trigger.
- **RELEASE INSTALL** — `tauri-plugin-updater` refuses to start without `plugins.updater.pubkey` in the merged config, so the plugin is compiled in only with the `updater` cargo feature, and only the release workflow turns it on, always together with `--config tauri.release.conf.json`. A `--features updater` build without that file panics at launch; `platform::RELEASE_UPDATE` is the feature, and it is what tells a release install from a working copy or the dev app. ⟵ 2026-11-21 release installers (#69)
- **RELEASE INSTALL** — The Windows installer cannot overwrite a `berth.exe` the daemon is running, and the daemon outlives every app update; `apps/desktop/src-tauri/nsis/hooks.nsh` renames it to `berth.old.exe` before copying (a running exe can be renamed) and deletes that file when it can. `berth upgrade` on Windows does the same swap. ⟵ 2026-11-21 release installers (#69)
- **MACOS WINDOW** — The overlay title bar (traffic lights over the web title bar) lives in `tauri.macos.conf.json`, not in a runtime call: tao's `set_decorations(true)` rebuilds the style mask without `FullSizeContentView`, and `hiddenTitle` has no setter. Config merging replaces the whole `windows` array, so `tauri.dev.conf.json` (passed with `--config`) would wipe it again; `apps/desktop/scripts/dev.mjs` adds `tauri.dev.macos.conf.json` after it on macOS, and a window field added to one of the four files belongs in the other three.
- **MACOS WORKING COPY** — The running exe is `app/<build-id>/Berth.app/Contents/MacOS/berth-desktop`, so `build.json` and `install-app.sh` sit beside `Berth.app`, and `platform::install_dir` maps the exe dir back to that build dir; writing into the bundle after `codesign` would break the signature.
