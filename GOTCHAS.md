# Gotchas

The traps that outlive the task that found them — a platform or tool quirk, a required ordering, a
signal that lies, a settled decision. One line each, grouped by area, each opening with the thing it
is about. Read the sections your task touches before you start: a line here is a mine somebody
already stepped on.

Every line ends with `⟵ <slug>` — the task write-up it was distilled from. Those write-ups are
not in the tree; they went with the old project-memory system in `0415b71` and live in git history:

```
git show 0415b71^:.claude/memory/entries/<slug>.md
```

Two things to know before trusting a line. **It describes what was true when it was written** — if
one names a file, flag or symbol, grep for it before relying on it. **All of it predates two renames**,
nebula to pacer before the first release and pacer to berth after 0.20: env vars are `BERTH_*`, the
data dir is berth's (see DATA DIR), the database is `berth.db` and the hook tag is `_berthManaged`. Lines below have been respelled; the `⟵` slugs have not, because they are
filenames in git history and only resolve spelled the way they were written.

The ALL-CAPS lead-in is the old memory log's index key, not the project vocabulary; `GLOSSARY.md`
holds the terms. Nothing enforces this file any more — the caps and the `make memory-check` that
kept them are gone. A line whose trap a test or a type now catches should be deleted, not kept for
history.

## The tree
- **EXTERNAL SESSION** — An archive mark is a watermark, not a flag: the desktop app hides the row only while the transcript's mtime (`updated_at`) is at or before the daemon's `archived_at`, so new activity brings it back without anyone deleting the mark, and a test that archives then appends to the transcript sees it return. Never let archive or restore touch the transcript file or the process running it.
- **EXTERNAL SESSION** — Claude Code's `/clear` keeps the process but starts a new session id (SessionStart `source: clear`): the agent row adopts the new id and the old transcript turns into an external session, so the daemon archives it right there.
- **ROOT WORKTREE** — `git rev-parse --show-toplevel` inside a linked worktree returns the worktree, not the repo; `git worktree list --porcelain` always lists the main checkout first and is the reliable root oracle. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **ROOT WORKTREE** — git will swap a root's and a worktree's branches (`git switch --ignore-other-worktrees <wt-branch>` succeeds in the root), so a "wrong" ROOT BADGE can be reality — check `git worktree list` first. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **TERMINAL SESSION** — The Aug 9 removal of terminals reads like a settled decision in the history and is not one (they came back) — don't cite it as precedent. ⟵ 2026-08-09-terminals-removed-then-brought-back
- **WORKSPACE** — `workspace = None` must survive for connections that never `Subscribe` — the one-shot `berth add`, whose workspace genuinely is the current default; don't default it at connect time. ⟵ 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **WORKSPACE** — A WORKSPACE is just a grouping of PROJECTS and the same PROJECT may belong to several — refusing to add a project already in another workspace was rejected by the user. ⟵ 2026-08-21-workspaces-and-the-o-t-e-hotkey-remap

## Processes and plumbing
- **DAEMON LOG** — DAEMON LOG records no hook traffic at `info` (`hook received` is `debug`; `hookEvent=` never appears), so the SQLITE STORE row (`claude_session_id` on `agents`) is the only cheap live oracle for status timing. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **DAEMON SETSID** — Garbage tokens on the terminal that started the daemon were a shell job-control fight over the controlling terminal, not vt100: a new process group is not enough — a new session makes zsh's `/dev/tty` open fail so it skips job-control init. ⟵ 2026-08-20-the-daemon-needs-its-own-session-not-just-a-process-group
- **DATA DIR** — The real DATA DIR is `~/Library/Application Support/dev.berth/` on macOS (`ProjectDirs::from("dev","","berth")`), `$XDG_DATA_HOME/berth` (else `~/.local/share/berth`) on Linux, `%APPDATA%\berth\data` on Windows; nothing prints it. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **DATA DIR** — The pacer → berth rename is a one-shot COPY in `pacer_migration::run`, called first thing in `main` for every subcommand: berth's DATA DIR existing at all is the "already migrated" flag, so anything that creates it before `main` runs (log init, a config write) silently skips the copy forever, and any `berth` run without `BERTH_DATA_DIR` (a test spawning `CARGO_BIN_EXE_berth`, a smoke check) snapshots the real pacer data into the real berth dir — give every such spawn its own `BERTH_DATA_DIR`. Old names live only in `berth-core/src/legacy.rs`.
- **DATA DIR** — Opening a WAL database read-only still creates its `-wal`/`-shm` when they are missing, so the migration file-copies `pacer.db` when no `pacer.db-wal` exists and only uses `VACUUM INTO` over a read-only connection when one does (a live or crashed pacer daemon); that is what leaves pacer's directory byte-identical. On Windows `directories` asks the shell for `FOLDERID_RoamingAppData`, so a temp `APPDATA` does not redirect the default path — test the copy with `PACER_DATA_DIR` plus `BERTH_DATA_DIR`.
- **LOGIN SHELL PATH** — `platform::login_shell_path()` costs one `$SHELL -l -i -c` start (capped at 3 s) and its result goes into the process env with `set_var`, so the desktop calls it as the first line of `desktop::run`, before tauri or tokio start a thread: a `getenv` on another thread (WebKit, any C library) races `setenv`. Moving it later or onto a thread needs every spawn site to take the PATH explicitly instead.
- **MIGRATION** — Migrations 2, 3, 7 and the migration-14 rebuild still spell out the divider columns and must — they already ran on every DB; only migration 18 drops them, so don't "tidy" old SQL. ⟵ 2026-08-25-project-dividers-removed-from-the-projects-column
- **PTY SESSION** — Agent PTYs get `TERM=xterm-256color` (`pty/mod.rs`) but inherit the daemon's `TERM_PROGRAM`, so `/terminal-setup` inside berth detects the terminal the daemon was first spawned from, not the one attached. ⟵ 2026-08-18-cmd-p-never-reaches-the-agent-in-terminal-app
- **RUNTIME DIR** — SUN_LEN is 104 bytes on macOS, so a RUNTIME DIR holding the DAEMON SOCKET must stay short: the default is `/tmp/berth-{uid}` or `$XDG_RUNTIME_DIR/berth`, `make dev` uses an 8-hex path hash (`/tmp/berth-dev-<8hex>`), never the worktree name; for a hand-set `BERTH_RUNTIME_DIR` use short dirs like `/tmp/nbws`. ⟵ 2026-08-26-one-nebula-per-checkout-auto-port-for-browser-per-path-dev-s; 2026-08-24-workspaces-are-per-instance-not-daemon-global
- **SQLITE STORE** — A `COALESCE(workspace_id, ?1)` inside a shared `*_COLUMNS` const makes every query using it bind a hidden first parameter; rusqlite only checks bind counts, so a `WHERE workspace_id = ?1` would silently COALESCE NULL rows — select the bare column and apply `DEFAULT_WORKSPACE_ID` in `row_to_project`. ⟵ 2026-08-27-workspace-wide-dedup-pass-named-literals-shared-helpers-nebu
- **SQLITE STORE** — `sqlite3 ".backup"` reads the WAL, so the snapshot is consistent with the daemon still running; a plain `cp berth.db` misses everything in `berth.db-wal`. ⟵ 2026-08-25-make-dev-showed-v0-4-0-and-no-projects
- **VENDORED VT100** — VENDORED VT100 is 0.16.2 (`vendor/vt100/Cargo.toml`), not the 0.15.2 older entries claim — grep every symbol the log names before relying on it. ⟵ 2026-08-27-terms-md-one-all-caps-name-per-thing-kept-by-project-terms
- **VENDORED VT100** — Codex is a ratatui inline-viewport app scrolling inside a top-anchored DECSTBM region (`ESC[1;{viewport_top}r`); stock vt100 0.15.2 `grid.rs` `scroll_up` discards lines scrolled out of a region, so codex scrollback stayed empty. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — `vendor/vt100` is a patched fork — do not upgrade or re-vendor it without re-applying the scroll-region patch. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VENDORED VT100** — Full-screen (alternate screen) apps are unaffected: that grid is created with zero scrollback capacity. ⟵ 2026-08-14-vendored-vt100-so-codex-scrollback-works
- **VERSION SKEW** — A PROTOCOL VERSION bump means the daemon still running from before the build refuses the new client until BERTH KILL (or MAKE CYCLE) restarts it — expected; the client offers the kill-and-restart. But `berth kill` is wrong advice when the *client* is the older side: the `berth` command respawns an identical daemon from `current_exe()` (`spawn_daemon` in `crates/berth/src/client.rs`). `buildstamp_path()` (`<runtime dir>/daemon.build`) holds only a content fingerprint of the daemon's exe, not where it lives — pidfile + `ps` names the binary. ⟵ 2026-08-28-r-renames-a-project-row-without-touching-its-folder; 2026-08-28-released-v0-15-0-by-cherry-picking-only-the-post-v0-14-0-del; 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis · re-hit ×2 2026-08-28 · retire: `pacer rename` over the HOOK RECEIVER instead of the versioned socket
- **VERSION SKEW** — The desktop app starts `berth daemon` from the `berth.exe` beside it (Windows searches the caller's directory before `PATH`), so after an app update the daemon is newer than `~\.cargo\bin\berth.exe`. Every PTY therefore gets the daemon's own directory first in `PATH` (`pty/own_dir.rs`), with the app's `current` link resolved to the build it points at. A unix agent launch goes through the login shell, whose profile can still put another `berth` in front. ⟵ 2026-11-11-berth-rename-v40-against-a-v41-daemon
- **VERSION SKEW** — A new `ClientRequest` variant needs the PROTOCOL VERSION bump too: the daemon's `read_frame` fails on an unknown variant and drops the whole connection, so an older daemon would kill the client instead of answering. The running `tauri dev` desktop rebuilds itself on the bump and turns Incompatible at once; rebuild and restart the dev daemon (`berth kill` with the dev `BERTH_RUNTIME_DIR`, `cargo build -p berth`, `berth daemon`) without stopping the app. ⟵ 2026-11-06-list-branches
- **VERSION SKEW** — Do not add a field to `ServerEvent::Incompatible`: a newer daemon sends it to an older client and rmp is positional, so those clients fail to decode it ("unexpected handshake reply"). ⟵ 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis

## Status and badges
- **DONE BADGE** — "Done" means read-vs-unread (`Agent::unseen`), not finished-vs-not — settled after two wrong readings; when a color is asked for "so it's obvious something needs addressing", use the flag that already means it. ⟵ 2026-08-27-done-reads-violet-and-says-done
- **DONE BADGE** — The counter is daemon-side, in the SQL `CASE` of `set_agent_status`, not `AgentStatusMachine` (which dedups unchanged statuses); NEEDS FEEDBACK → FINISHED counts, FRESH → FINISHED does not. ⟵ 2026-08-26-unwatched-finishes-count-on-the-project-and-worktree-rows
- **PROGRESS SCANNER** — Esc-cancelling a Claude turn fires no hook at all: `Stop` skips user interrupts and `idle_prompt` needs 60s quiet AND no keyboard touch (Claude Code 2.1.241: only `UserPromptSubmit` then `SessionEnd` fired). ⟵ 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — Claude Code 2.1.270, Codex and cursor-agent emit **no OSC 9;4 at all** — not at startup, not on submit, not on a cancel — so `progress_busy` reads `None` forever and every Claude row wedged on yellow after `Esc`; the title is Claude's fallback (see TITLE SCANNER). Re-check a new release with `cargo test -p berth-daemon --test conpty_progress_probe -- --ignored`. ⟵ 2026-09-15 escape-did-not-cancel-the-animation; 2026-08-23-cancelling-claude-left-the-status-stuck
- **PROGRESS SCANNER** — `ProgressScanner::feed` reports *edges*, so an end-of-turn that lands before the status moves (the cancel, then the permission hook) is spent and nothing is left to un-wedge the row; `AgentStatusMachine::tick` reads the *level* (`PtySession::progress_busy`) as the backstop, and needs two sightings so a `UserPromptSubmit` that beat the CLI's own busy byte can't read as finished.
- **STATUS MACHINE** — `SessionEnded` only flips AGENT STATUS from RUNNING/NEEDS FEEDBACK, so a row that dies at FRESH (a failed cloud create) stays gray — `cloud_session_id` and `alive:false` are the only tells. ⟵ 2026-08-26-cloud-rows-re-enter-their-session-on-restart
- **STOP GATE** — `TaskStop`-killing a BACKGROUND SUBAGENT delivers no `SubagentStop` (a normal completion does), and `Esc` mid-turn kills the turn's background workers the same silent way — the orphan then gates every later turn of that session. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no; 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — A killed subagent is only distinguishable from a live silent one on disk: `"stoppedByUser": true` in `<transcript>/subagents/agent-<id>.meta.json`, read by `subagents.rs` on tick, where `<transcript>` is the payload's `transcript_path` minus `.jsonl`. Claude-only — codex and cursor still wait out the 30 min QUIET GRACE. ⟵ 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — `UserPromptSubmit` resets `stop_held` and the quiet clock but does *not* clear the tracked set (deliberately: background workers outlive a prompt), so an orphan survives every later prompt and the quiet clock restarts from each turn's hold, not from the kill. ⟵ 2026-09-07-a-session-that-had-answered-kept-sweeping-yellow-for-half-an
- **STOP GATE** — Subagent tool traffic reaches the STATUS MACHINE only for hooked tools (`PostToolUse` `Bash|EnterWorktree|ExitWorktree`, `AskUserQuestion`): a Read/Grep-only worker shows life only at start and stop, so the quiet clock must stay generous. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **STOP GATE** — The quiet clock counts from the last sign of life, not from the held Stop — a test written "from the hold" is off by the SubagentStart→Stop gap. ⟵ 2026-08-28-background-subagents-turned-the-session-green-idle-prompt-no
- **TITLE SCANNER** — The OSC 0 title glyph (`✳` idle, `◐`/`◑` working) is the end-of-turn signal left once OSC 9;4 went away, but it reads idle while a permission prompt waits too — so `TitleIdle` may only close out a turn already on RUNNING, never one on NEEDS FEEDBACK, and may never start one. Relaxing that gate greens out every agent waiting on the user. ⟵ 2026-09-15 escape-did-not-cancel-the-animation
- **TITLE SCANNER** — The glyph is only there because `showStatusInTerminalTab` is off by default; turning it on strips the prefix and the fallback goes quiet (not wrong — cancels just wedge again). Codex and cursor title themselves without it, so the path is inert for them either way. ⟵ 2026-09-15 escape-did-not-cancel-the-animation

## Desktop web UI
- **PHONE LAYOUT** — The desktop web UI goes phone-shaped on `<html data-vr-viewport="phone">`, which `installViewport` (`packages/ui-kit/src/viewport.ts`) sets from `PHONE_QUERY` in `@ui/tokens`; a component never writes a width media query, it uses the `vr-*` primitives in `packages/ui-kit/src/responsive.css`. Growing a touch target with a `::after` past the button's box steals taps from the next row of a dense list (later siblings paint on top), so the kit sizes rows (`--vr-size-row`) and icon buttons instead. ⟵ 2026-11-06-the-web-ui-fits-a-phone
- **PHONE EMULATION** — In WebView2, CDP `Emulation.setDeviceMetricsOverride` with `deviceScaleFactor: 3` changes `devicePixelRatio` but not `devicePixelContentBoxSize` (it stays at the monitor's scale), so the xterm WebGL canvas gets a 1.25x backing store and 3x glyphs: the terminal looks 2.4x too big and clipped on the right. That is the emulator, not the app; judge the terminal at `deviceScaleFactor: 0`.
- **DOCKVIEW HMR** — A dock panel with `renderer: 'always'` keeps the component instance it was created with across Vite HMR, so a template change inside one looks unapplied; press F5 before judging it. ⟵ 2026-11-06-the-web-ui-fits-a-phone

## Agents and hooks
- **HOOK TAG** — berth treats pacer's hook groups (`_pacerManaged`, or a command naming `PACER_AGENT_ID`) as its own, so a berth spawn replaces them; pacer 0.20 does not know `_berthManaged`, so a pacer spawn in the same checkout or `~/.codex` adds its groups back beside berth's. Both sets stay inert outside their own sessions only because the daemon scrubs the other product's `*_AGENT_ID`/`*_API_*` from every PTY (`env::AGENT_SESSION_VARS`): drop the `PACER_*` names from that list and a berth started inside a pacer pane posts its sessions' hooks to pacer's daemon. The `Bash(pacer …)` permission rules are left in `settings.local.json` on purpose.
- **AGENT KIND** — Every CLI takes a trailing positional prompt (`claude [prompt]`, `codex [PROMPT]` / `codex resume [SESSION_ID] [PROMPT]`, `cursor-agent [prompt...]`), but only Claude's `--resume <sid> "<prompt>"` is verified live — the RELOCATION PROMPT is Claude-only for that reason. ⟵ 2026-08-28-agent-presets-launch-a-session-with-a-composed-first-prompt · retire: a live codex/cursor resume-with-prompt check
- **AUTO-TITLE** — The `berth rename` every session issues before anything else is injected context from the AUTO-TITLE INSTRUCTION, not something the user typed — don't mistake it for part of the request. ⟵ 2026-08-20-sessions-auto-rename-themselves
- **CLI RENAME** — No hook fires on Claude's or Codex's `/rename`. Claude rewrites `<transcript stem>/custom-title.json` (and `~/.claude/sessions/<pid>.json` `name` with `nameSource: "user"`) and re-appends the same `custom-title` line to the transcript all the time, so a line is not news; Codex appends `{id, thread_name, updated_at}` to `$CODEX_HOME/session_index.jsonl`. A rename is a change of `agents.cli_title`, never a difference from `name`, or a berth rename is undone on the next sampler tick (`crate::cli_title`).
- **CLI RENAME** — A `claude` the user starts by hand in a terminal is found by pid: Claude keeps `<CLAUDE_CONFIG_DIR or ~/.claude>/sessions/<pid>.json` while it runs, and only `nameSource: "user"` is a `/rename` (`"derived"` is Claude's own name; `formerNames` lists the old ones). The sampler walks the terminal's process subtree for it and stores `terminals.cli_title` the same way as agents. Codex keeps no record by pid, so a hand-started Codex in a terminal is not followed. No supported way exists to push a berth name into Claude's own title, so `/resume` keeps Claude's.
- **CLI RENAME** — The same `<pid>.json` carries `sessionId`, so the sampler also stores `terminals.session_id`, the conversation a terminal last ran; the desktop app ties a closed conversation to its dead terminal by that id, never by the terminal's name. A Claude that exits before a sampler tick, or ran before the daemon recorded it, leaves no id, and its conversation lists on its own.
- **AUTO-TITLE** — Untitled `agent-N` rows *after* a prompt are VERSION SKEW, not a hook failure: the injection is unversioned HTTP but the bare `berth rename` resolves on PATH, so any session's `make install` untitles every SESSION a still-running (dev) daemon starts afterwards — date it by `auto_title_pending=1` rows' `created_at` vs `~/.cargo/bin/berth`'s mtime. ⟵ 2026-08-28-agent-n-rows-after-prompting-are-version-skew-not-auto-title
- **CLI PROBE** — Running `claude` from an untrusted dir (the scratchpad) hangs on the workspace-trust prompt; probe CLI behaviour from the repo checkout. ⟵ 2026-08-26-cloud-rows-re-enter-their-session-on-restart
- **CODEX HOOK DIALECT** — Codex trust is keyed by the hook file's absolute path (`~/.codex/config.toml` `[hooks.state."<abs path>:<event>:<g>:<h>"]` `trusted_hash` is not a plain sha256 — don't precompute it); a project-local `.codex/hooks.json` re-prompts in every worktree, and unanswered means hooks never run. ⟵ 2026-08-22-codex-hooks-moved-to-codex
- **CODEX HOOK DIALECT** — Codex discards raw hook stdout; context injection only works via `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"…"}}` — Claude Code accepts the same envelope. ⟵ 2026-08-22-codex-hooks-moved-to-codex
- **CODEX HOOK DIALECT** — `codex exec` does run hooks once trusted (a fast harness) but cannot answer the trust modal — grant trust first with one interactive run. ⟵ 2026-08-22-codex-hooks-moved-to-codex
- **CURSOR HOOK DIALECT** — Cursor silently ignores Claude-shaped PascalCase hook groups — no error, no status ever phones home. ⟵ 2026-08-20-cursor-s-hooks-are-not-claude-shaped
- **CURSOR HOOK DIALECT** — Dialect: camelCase events (`sessionStart`, `beforeSubmitPrompt`, `stop`, `subagentStart/Stop`, `sessionEnd`), flat `{"command": …}` entries (no `hooks` array, no `type`), required top-level `"version": 1`; hooks must print `{"continue": true}` or gating events degrade. ⟵ 2026-08-20-cursor-s-hooks-are-not-claude-shaped
- **CURSOR HOOK DIALECT** — Payloads carry `session_id` == `conversation_id` (the `--resume` chatId), have no `cwd` (use `workspace_roots[0]`), and subagent hooks use `subagent_id`, not `agent_id`. ⟵ 2026-08-20-cursor-s-hooks-are-not-claude-shaped
- **CURSOR HOOK DIALECT** — `beforeSubmitPrompt` and `stop` fire only in interactive TUI mode — never conclude hooks are broken from a `-p` test; drive one with timed keystrokes through `script -q /dev/null cursor-agent --force --trust`. ⟵ 2026-08-20-cursor-s-hooks-are-not-claude-shaped
- **CURSOR HOOK DIALECT** — Cursor has no PermissionRequest hook and berth runs `cursor-agent --force`, so cursor agents report busy/idle but never NEEDS FEEDBACK — expected, not a bug. ⟵ 2026-08-14-codex-and-cursor-as-agent-kinds
- **LOGIN SHELL WRAP** — A fresh `claude` under `zsh -l -i` is 0.67 s to first byte and 1.47 s to a painted screen (before `--resume`), so six at once is the whole 5–10 s — and benchmark agent CLIs one at a time (4 at once got the shell OOM-killed, exit 137). ⟵ 2026-08-26-a-workspace-switch-cold-booted-a-fleet-of-claude-clis
- **LOGIN SHELL WRAP** — `BERTH_AGENT_CMD` must skip the login-shell wrap: otherwise `~/.zprofile` resets PATH and the real `claude` CLI launches instead of the STUB AGENT. ⟵ 2026-08-14-agents-spawn-through-a-login-shell
- **MANAGED HOOKS** — A machine-wide `HTTP_PROXY` swallows the loopback hook call: curl does not honour `NO_PROXY` masks like `127.*`, the proxy answers 502 and every session stays `fresh` with no `claude_session_id`, so a daemon restart boots a blank Claude instead of resuming. `hook_curl` carries `--noproxy '*'` for that reason. Diagnose with a manual curl to the hook port from `daemon.log`: 502 is the proxy, 401 is the daemon. ⟵ 2026-09-13 frontend-session-came-back-empty-after-a-daemon-restart
- **MANAGED HOOKS** — The real hooks are `curl` to `$BERTH_API_URL/api/hooks/...` (loopback HTTP, unversioned, fail-soft), so a PROTOCOL VERSION bump can only break the injected instructions, never status. ⟵ 2026-08-26-nebula-rename-broke-on-a-protocol-skew-the-error-message-mis
- **MANAGED HOOKS** — Claude snapshots hooks at session start, so any hook-set change only reaches newly spawned sessions. ⟵ 2026-08-18-sessions-re-home-into-the-worktree-they-create
- **MODEL / EFFORT** — `claude` takes `--model <alias>` and `--effort <low|…|max>`; `codex` takes `-m/--model` and effort only via `-c model_reasoning_effort=<…>`; `cursor-agent` has no knobs; "default" always means pass no flag. ⟵ 2026-08-14-codex-and-cursor-as-agent-kinds
- **WORKTREE GUIDANCE** — `registry.rs`'s test helper `guided()` spells the exact composed `--append-system-prompt`: a guidance constant added to `agent_spawn_command_with` must be joined into it in the same order or `spawn_command_per_kind_resume_shapes` fails on a string diff; a new daemon concern can `impl Daemon` from its own module (`sibling.rs`) since `store`/`events` are `pub` and `create_agent` is `pub(crate)`. ⟵ 2026-08-28-nebula-spawn-starts-a-sibling-session-from-inside-a-prompt

## Daemon mechanisms
- **IDLE REAPER** — Reaping is switchable off entirely (`session_idle_timeout = off`) because agents may be running long jobs the status machine cannot see; the PIN exemption that used to protect them was removed with PIN on 2026-08-28 — do not reintroduce a per-session spare without the user. ⟵ 2026-08-20-idle-session-reaping-and-metrics; 2026-08-28-pin-and-the-recent-group-are-gone-one-flat-list-in-recency
- **METRICS** — `GetMetrics` no longer sweeps: `crate::sampler` is the single owner of the CPU delta and the transcript offsets, and the request reads its last sample. - **PREWARM POOL** — Each WARM SPARE lives 15 min (`PREWARM_MAX_AGE`): 7 projects ≈ 7 idle `claude`s ≈ 1.7 GB; the opt-out is `prewarm_agents` in CONFIG.JSON; turning it off leaves the live spares to age out. ⟵ 2026-08-27-the-memory-modal-s-unknown-agents-are-the-prewarm-pool
- **PREWARM POOL** — `ps -Eo command -p <pid>` shows a daemon child's `BERTH_AGENT_ID` / `BERTH_DATA_DIR` (macOS `ps -axo … -p` ignores `-p`, drop `-a`); `grep prewarm <data_dir>/state/daemon.log` maps the id to its spawn — branch only, so `main` repeats across projects. ⟵ 2026-08-27-the-memory-modal-s-unknown-agents-are-the-prewarm-pool
- **AGENT MEMORY** — One `claude.exe` holds ~220 MB private working set idle and 300–400 MB after work (550–750 MB commit); its ~260 MB of code is image-mapped and shared between processes. - **WORKTREE SEED** — `git ls-files --others --ignored --exclude-standard --directory` collapses a directory ignored *in full* into one `dir/` entry, so a symlink parked inside it (`.claude/skills/<skill>`) never appears; skipping every `dir/` entry therefore drops exactly the links `worktree_seed` exists to carry, which is why it also does a shallow pass inside them. - **WORKTREE SYNC** — `git worktree list` may print canonical paths while `add_worktree` returns the tempdir spelling (`/var/…` vs `/private/var/…` on macOS) — canonicalize both sides when a test needs to find the entry. ⟵ 2026-08-27-a-paused-rebase-renamed-the-worktree-row-to-detached
- **WORKTREE SYNC** — A probe that can't read anything is not a fingerprint: `.git` is a *file* in a linked worktree, so `.git/HEAD` stamps were `None == None` and the project never synced; never cache a `None` stamp. ⟵ 2026-08-25-the-root-row-named-after-a-worktree
- **WORKTREE CLEANUP** — `rev-list base..HEAD` = 0 also holds for a branch created a minute ago with no commits, so reachability alone would offer a fresh worktree as merged; `apps/desktop/src-tauri/src/cleanup.rs` counts it merged only when the branch reflog moved past its creation entry. - **WORKTREE CLEANUP** — On Windows `git worktree remove --force` and recursive deletes descend into a `node_modules` junction and empty the main checkout's copy; unlink every reparse point with `lstat` (no follow) before the daemon's `DeleteWorktree`. ⟵ 2026-11-06-worktree-cleanup

## Windows port
- **CONPTY INPUT** — The Windows 10 inbox ConPTY (conhost 19041) passes a child's kitty push (`CSI > 5 u`) through on *output* but drops CSI-u on *input*, and drops win32-input-mode records while the mode is off. A modern `conpty.dll` on PATH (Zed's 1.23, WezTerm's) passes CSI-u through. ## Other
- **RELEASE** — The `version` bump in the root `Cargo.toml` *is* the release: landing one on `main` builds three targets (macOS arm64/x64, Windows x64), tags the commit and publishes the GitHub release with the archives `install.sh` downloads. Never bump it as part of unrelated work.
- **RELEASE** — A tag or release created with `GITHUB_TOKEN` starts no workflow — GitHub's guard against a workflow triggering itself. So a release cannot hang off a tag CI pushed, and nothing can hang off `release: { types: [published] }`. `release.yml` does all of it in one run; the tag is the record of what shipped, not the trigger.
- **MACOS WINDOW** — The overlay title bar (traffic lights over the web title bar) lives in `tauri.macos.conf.json`, not in a runtime call: tao's `set_decorations(true)` rebuilds the style mask without `FullSizeContentView`, and `hiddenTitle` has no setter. Config merging replaces the whole `windows` array, so `tauri.dev.conf.json` (passed with `--config`) would wipe it again; `apps/desktop/scripts/dev.mjs` adds `tauri.dev.macos.conf.json` after it on macOS, and a window field added to one of the four files belongs in the other three.
- **MACOS WORKING COPY** — The running exe is `app/<build-id>/Berth.app/Contents/MacOS/berth-desktop`, so `build.json` and `install-app.sh` sit beside `Berth.app`, and `platform::install_dir` maps the exe dir back to that build dir; writing into the bundle after `codesign` would break the signature.
